# Crimson Noir Script ebook: technical and commercial-rights audit

**Audit date:** 2026-11-18. **Compared against:** repository snapshot `7bf2c96652db9d8b9cc4d97a46439587c1ee6edb`, especially `src/07_Execute_Actions/terminal/noirscript/`, `docs/crimson-noir-script.md`, the application terminal, first-walk implementation, and gate. **Status:** beta, not a legal clearance or a finding that every statement is correct. This report identifies issues fixed and unresolved work; it is not legal advice.

## Commercial release: do not assume clearance

1. **Embedded proprietary engine — release blocker unless rights are established.** The HTML contains a JavaScript bundle of the current NoirScript source under `src/07_Execute_Actions/terminal/noirscript/`, plus a modified `NoirSession` with a read-only `inspect()` method. Source headers and the repository's `LICENSE` and `LICENSES/LicenseRef-CrimsonNoir-Proprietary.txt` identify that code as Copyright (c) 2026 Julian Cassius Subban, all rights reserved. The stated evaluation permission is noncommercial; public repository access or a download link does not itself grant commercial distribution, sale, modification, or sublicense rights. Confirm the seller is the rights holder or obtain a written license covering the modified bundled engine, offline distribution to buyers, and sale in the intended territories. An acknowledgement in the ebook does not itself grant those rights. Prior releases have distinct licensing; that does not establish rights to the current bundled code.
2. **Branding — release blocker until authorized and cleared.** The book uses Crimson Noir and Agent City names and a five-tower illustration in the project's visual style. `LICENSE` and `NOTICE.md` identify names, logos, trade dress and visual art as reserved material. Confirm authorization and any design rights for the book cover, user interface, marketing images, title, and distribution. References to third-party companies, models and technology appear in the text; references are not necessarily infringement, but use in a title, cover or advertising can raise separate questions. Avoid implying endorsement without permission. The use of Vantablack as a generic color description was removed; Surrey NanoSystems identifies Vantablack as its trademark.
3. **Ownership and contributions to this edition remain unverified.** The root-level ebook is not individually listed in the root license and has no independent grant establishing who owns every contribution. Its text, generated illustrations, code snippets, prior edits, and outside contributions need a provenance and rights review. No statement here determines the seller's identity, ownership, or entitlement to sell. Retain creation records and any contributor agreements; check platform terms and applicable law for generated material.
4. **MIT documentation.** Repository `docs/` is identified as MIT-licensed; the ebook draws on repository technical material. The repository's full MIT copyright and permission notice is now included in the ebook's offline Appendix. MIT terms permit commercial use subject to their conditions, but do not grant rights in separately proprietary source or reserved branding.
5. **KaTeX 0.19.1 and fonts.** The HTML includes KaTeX JavaScript and adapted CSS with 20 embedded WOFF2 fonts. The bundled JavaScript matched the local installed KaTeX 0.19.1 `dist/katex.min.js` byte-for-byte; all 20 decoded WOFF2 files matched files in that package by SHA-256. The full KaTeX package MIT notice (Copyright 2013–2020 Khan Academy and contributors) was already in the HTML source. The separate KaTeX fonts project publishes an MIT license with Copyright 2018 Khan Academy; its full notice is now visible in the offline Appendix. Maintain the applicable notices in distributed copies. Upstream font history and any additional provenance questions still warrant review before release; a matching package file is not an independent legal title opinion.
6. **ORC is not a blanket software or brand license.** The repository says ORC covers its designated game mechanics, not the current source code or reserved materials. If distributing a derivative of designated ORC material, determine separately whether the license applies, which material is used, and what attribution and notice obligations apply. The book is not cleared merely because the repository mentions ORC.
7. **Trademark search and other rights are unfinished.** A real clearance search should cover exact and similar names, related ebook/software goods and services, logos, federal and state registers, common-law use, and target-country registers. No comprehensive registry or common-law search was performed. A lawyer should assess title, product presentation, source attribution, quotations, marketing, and all proposed territories. Citations alone are not a license; fair use is fact-specific and is not determined by a fixed word count.

## Substantive technical corrections made

| Area | Finding verified against source or runtime | Correction |
| --- | --- | --- |
| Vectors | `dot(...)` is not an intrinsic; `DOT_F32X4` is not an opcode. A four-lane product can use vector multiply then `hsum`. `v * 2.0` and `v == v` for `f32x4` are rejected; masks use `veq` and `all`. | Corrected the vector table, examples, intrinsic catalogue and speed claims. |
| VM accounting | A VM opcode/step does not imply one physical SIMD instruction or a measured 4× speedup. Cell moves may incur a `floor(w/16)` extra step charge. A runtime fault does not roll back earlier global mutations. | Removed hardware and rollback guarantees; clarified accounting and persistence. |
| Finite Rule 110 | A finite, bounded example does not prove this implementation can run every algorithm or arbitrarily large models. | Clarified theoretical universality versus the finite demonstration. |
| Approximate attention | Lab 07 clamps the exponential input to `[-20, 20]`. For its printed example the two future-token weights are about `9.969312e-10`, not zero. | Corrected clamp range and explicitly labeled the mask approximate, including what strict masking requires. Lab behavior was not silently altered. |
| RMSNorm and dot products | Epsilon prevents exact scale invariance and exact fixed norm in general; nonuniform gain also changes the norm. Self-dot is not always the largest score. | Corrected mathematical descriptions, example code and assumptions. |
| Safety and security | The first-walk seal uses a nonce and 32-bit FNV-1a, a non-cryptographic hash. A simplified braking envelope and in-game guardrails do not establish real-world safety or an unguessable token. | Removed the security and collision guarantees and distinguished simulation from live application. |
| Evidence and performance | The cited bridge GC figures were from a Node 22 worker-thread benchmark, not physical-device or browser measurements. Earlier Lab 04/06 step counts and an RMS value were stale. | Qualified the benchmark and updated or removed unsupported figures. |
| Reference | `for` bounds can be `i32` or `u32`; unsigned vector column loads and scalar rounding intrinsics were omitted; `clamp` is scalar. | Corrected the Appendix. |
| Local UI | The city host and writes are simulated; the attention heatmap is illustrative rather than extracted from the VM, and displayed probabilities are calculated in JavaScript. | Made these distinctions more prominent, and separated them from the live application's features. |
| Provenance | Proprietary engine attribution was removed by bundling; notices needed to travel with the single offline file. | Added an embedded engine notice and visible third-party/repository MIT notices. These notices do not authorize sale. |

The ebook keeps the engine and examples intact, including the imperfect finite attention mask, rather than changing example results without reworking the lesson. It should not be used as a real-world safety system.

## Checks performed

- **Source tests:** `node --test --test-reporter=dot tools/ebook/accuracy.test.mjs src/07_Execute_Actions/terminal/noirscript/*.test.ts` — 85 tests passed (81 existing and 4 new audit regressions). The new tests compare source and bundled engines for vector failures, `hsum`, runtime fault persistence and Lab 07's actual future weights, and check for included notices.
- **18 embedded labs:** in headless Chromium, each original, one-line and multi-line version ran without a VM error under its example simulated host; the two generated payload forms had identical output and VM step counts, fit the 8,192-character command limit, and disassembled. This checks the chosen samples, not all inputs or live-city behavior.
- **Presentation:** headless Chromium at desktop and emulated 390 px, 375 px, 320 px and landscape touch layouts checked 14 lesson maps, quiz interactions, navigation, graphics controls, settings, offline requests, and overflow. A scripts-disabled check confirmed 14 readable lessons. These are emulations, not tests of physical phones, iOS Safari/WebKit, Firefox, GPU variants, assistive technologies, or all possible browser file-opening policies.
- **Dependency matching:** embedded NoirScript bundle was identical to the locally produced bundle; embedded KaTeX JS and all 20 WOFF2 assets matched the local package. The build bundle includes an added `inspect()` method. The source-to-bundle comparison does not prove the rest of the HTML is independently authored or licensed.
- **Repository header checker:** `node tools/license/headers.mjs check` passed. This checker does not determine legal ownership or commercial rights.

## Remaining work before a sale

- Confirm the rights holder, scope of their commercial license, permitted buyer redistribution, cover/brand rights and territory list. Have an IP lawyer review these documents and perform the clearance search. Do not market this edition as authorized, endorsed, legally cleared, or guaranteed compliant without that review.
- Perform a line-by-line editorial and numerical review of the remaining large body of advanced mathematics, historical citations, GPU performance estimates, platform/deployment details and product descriptions. Several are simplified; the checks above are not an exhaustive verification. Verify all research citations, publication details, permissions for any reused expressive material, and whether numerical examples match their assumptions. Remove or qualify any unverified benchmark and safety claims.
- Run the complete workflow on real Android browsers and iPhone/iPad Safari using the actual downloaded file, including local-file JavaScript restrictions, touch navigation, fallback navigation, controls, copy/paste, zoom and offline launch. Test desktop Firefox/Safari, keyboard and assistive technologies. No guarantee of universal CPU/GPU support or accessibility compliance has been established.
- Keep the bundled engine synchronized with the intended application version, document the build inputs and preserve applicable notices for every shipped edition. Test every lab with the actual app where applicable, using a non-production environment; the included host is a simulation.
